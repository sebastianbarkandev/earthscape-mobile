# CLAUDE.md — Earthscape Mobile

React Native app (Expo, TypeScript, expo-router) for Earthscape: aerial-video platform (police/utility flight footage + synced flight-path maps). This repo is a **client** of the existing Earthscape Flask API (separate `earthscape` repo: Flask + Flask-Security + SQLAlchemy/Alembic + Postgres/PostGIS + Celery + S3/CloudFront). This repo contains **zero backend code**. Backend changes are additive-only, in the earthscape repo, on feature branches — the production website shares every endpoint; never change an existing response shape.

## Commands
- Dev: `npx expo start` (backend = earthscape repo's `docker compose up`: nginx proxy on **port 80** → `http://demo.earthscape.localdocker`; the API container itself is :5001. There is NO port 8000.)
- Device build: `npx expo run:ios --device` (required after adding native modules)
- Video/HLS must be tested on a PHYSICAL iPhone; the Simulator is unreliable for AVPlayer.
- `expo-asset`/`expo-constants`/`expo-file-system`/`expo-font`/`expo-keep-awake`/`expo-linking` are direct deps ONLY to fix native linking — do not remove them. The first five: npm nests `expo`'s own native deps under `node_modules/expo/node_modules`, where expo-modules-autolinking (globs one level deep per search path) can't see them, so their pods never link → `Cannot find native module 'ExpoAsset'` at startup. `expo-linking`: `expo-router@5.0.7` asks for `"*"`, so npm installs the SDK 57 build (57.0.7) whose podspec autolinking can't consume → `Cannot find native module 'ExpoLinking'`; it must stay pinned to SDK 53's `~7.1.7`.
- Native deps added for the video page: `react-native-svg` (timeline/graphs), `expo-sharing` + `expo-media-library` (downloads/screenshots → share sheet / Photos), `expo-clipboard`. JS: `@expo/vector-icons` (FontAwesome6, same glyph names as the web's `fa-solid`), `filesize@^10` + `lodash` (deps of the verbatim `formatFlightPointValue.js`). All verified in `ExpoModulesProvider.swift` 2026-08-25.
- Metro tripwire: NEVER start Metro with `CI=1` / `CI=true` — Expo CLI then disables file watching ("Metro is running in CI mode, reloads are disabled") and every edit is silently ignored until a `--clear` restart. For a non-interactive terminal use `npx expo start < /dev/null` instead.
- After ANY dependency change: `npx expo-modules-autolinking resolve -p apple` must list every native module, each pod must appear in `ios/Podfile.lock`, and `ios/Pods/Target Support Files/Pods-Earthscape/ExpoModulesProvider.swift` is the ground truth for what the binary actually registers. Then `pod install` + rebuild.

## Hard rules (each verified against backend source)
1. **Base URL = org subdomain** (`https://{sub}.earthscape.com`), composed in `src/common/config.ts` as `{scheme}://{sub}.{baseDomain}`. **Dev is NOT a LAN IP** — `get_settings()` (app/__init__.py:345) splits `Host` on `.` and redirects to shotover.com when the first label matches no `Organization.subdomain`; `192.168.10.184:8000` yields subdomain `192` and 302s away. Use a 3+ label host: `demo.earthscape.localdocker` (backend repo's `/etc/hosts` convention, works in the Simulator) or `demo.192-168-10-184.nip.io` on device. A `:port` in Host is tolerated (it lands in the last label), an IP literal is not. **Never the `api.` subdomain for org data**: org loading is skipped there, and `login_required_but_demo_okay`/`requires_setting` dereference `g.organization`/`g.settings` — they crash or 403. `api.` is used for exactly one thing: the org-less `resolve_org` lookup — and `resolve_org` itself ignores the loaded org, so `EXPO_PUBLIC_API_LOOKUP_HOST` may point it at any org host of the *same deployment* (stage has no `api-stage`; `api.earthscape.com` is production).
2. **Auth = Flask-Security 5.x session cookie.** `LoginForm` is stock Flask-Security (fields: `email`, `password`, `remember`). Login: `POST /signin`, JSON body, `Accept: application/json` → JSON response + session cookie (`SECURITY_LOGIN_URL='/signin'`, `SECURITY_LOGOUT_URL='/signout'` in config/default.py — NOT Flask-Security's `/login` defaults). The form takes email+password only; the org comes from the Host, so mobile resolves it first via `resolve_org`. All fetches include credentials (matches the web repo's `EventsApi`/`TagApi` convention). CSRF: server-side monkeypatch exempts JSON content-type and `/api/`+`/v1/` paths — do not send CSRF tokens. Do NOT build JWT auth (the backend's JWT pieces are only for live WebRTC viewer-session tokens + a public-key endpoint). Store only subdomain + login flag in expo-secure-store — never the password.
   - **Demo escape hatch:** orgs with `is_demo=True` bypass auth entirely in `login_required_but_demo_okay`.
   - **MFA:** orgs with `REQUIRE_MFA` or users with `authy_id` get redirected to TOTP flows — use a non-MFA test user; do not build MFA screens.
3. **Video = expo-video only, native controls OFF** (custom `PlayerControls`, web PlaybackControlProgressBar parity: scrubber in video-seconds, ±10s / ±1/30s paused, speed 0.5–3×, mute, fullscreen via `VideoView.enterFullscreen`, Go live = `seekBy(86400)`). VOD source: `hls_stream_url` (fallback `mp4_url`) from the event payload. Live source: `GET /live/{live_stream_id}/playlist.m3u8` (server-cached HLS; supports `?token=` share tokens). Media URLs are sometimes absolute (CloudFront) and sometimes server-relative (live playlist via url_for) — always resolve through `resolveMediaUrl` in config.ts. Do NOT implement WebRTC/mediasoup/viewer-session — that's the web live path.
4. **Map = react-native-maps** (Apple Maps, `mapType="hybrid"`). Flight path Polyline = `map.data.loc`; target path Polyline = `map.data.target`; aircraft Marker pos = `getClosestPointValueOrNull(map.data.loc, currentUtc)`, rotation = closest `acft_hdg`; footprint Polygon. Series values arrive `[lat, lon]` (backend ST_FlipCoordinates). Web parity NOT wanted: no KML, TAK, heatmap, drawing tools, locate control.
5. **`src/common/lib/` contains verbatim ports — never rewrite, "improve," or reformat them; wrap if needed:**
   - `TimeMapper.js`: `createTimeMapper(startUtc, videoTimeUtcTimeMap) → {startUtc, videoTimeUtcTimeMap, videoToUtc(t), utcToVideo(t)}`. Handles gap-compensated videos. API sends snake_case `time_mapping` entries (`video_start`…) — convert keys before constructing (done in playerSlice.toMapperSpec). ALL video↔UTC conversion goes through this; naive `start + seconds` math is WRONG.
   - `timeSeries.js`: series = arrays of `[utc, value]`. `getClosestPointValueOrNull(series, utc)` (binary search; clamps to edge values out of range — keeps the aircraft pinned at path ends), `getLastValueOrNull(series)` (live-follow mode).
   - `mergeGraphData.js`: verbatim web copy (two-level `{category:{name:series}}` merge). Sibling `.d.ts` files describe all three libs for TypeScript — edit the `.d.ts`, never the `.js`.
   - Mappers hold functions and are never stored in Redux: keep the spec `{startUtc, videoTimeUtcTimeMap}` in state, re-create via `createTimeMapper` at use sites (`useTimeMapper` hook — the web does the same).
6. **State = Redux Toolkit, slim**: `auth`, `library`, `player`, `graph` slices only (web has ~24 — do not mirror them). The native video player is the source of truth for paused/rate/muted — `player.playback` only MIRRORS its events (a store-driven pause loop re-pauses after buffering); controls act through the `PlayerVideoHandle` ref. `reference/eventSlice.js` maps the domain — read for shapes/endpoints, never copy logic (it's bound to window/document/Jinja globals; mobile has `src/common/config.ts` instead).
7. **Styling = StyleSheet + `src/common/theme.ts`** — tokens extracted from web player.scss: `accent #FB8333 / hover #FF9B58 / active #E9741F / tint #FFF3EA; bg #F9F9F9, surface #FFF, bgSubtle #F2F2F2, bgHover #E9E9E9, bgActive #DCDCDC; text #0F0F0F / #606060 / #909090; border #E5E5E5 / #D3D3D3; danger #C62828, success #2E7D32, live #CC0000; radius 6/12/16/pill`. No SCSS, no Tailwind, no invented colors.

## API contracts (traced to backend source; times are UTC epoch floats unless noted)
- `POST /api/v1/auth/resolve_org` (on `api.{baseDomain}`, no org context, CSRF-exempt) — JSON `{email, password}` → `{organizations:[{subdomain, name}]}`; uniform 401 `{msg}` for unknown email OR wrong password. Added on the `earthscape-mobile` branch of the earthscape repo.
- `POST /signin` — JSON `{email, password, remember}` → `eswsessid` cookie (~24.6h) + 200 `{meta:{code:200}, response:{user:{}, csrf_token}}`. Bad password → **400** `{meta:{code:400}, response:{field_errors:{password:[..]}, errors:[..]}}`. Already signed in → 400 `errors:['You can only access this endpoint when not logged in.']`. `remember:true` (NOT defaulted for JSON bodies) additionally sets a 1-year `remember_token` cookie — send it, or users re-login daily.
- `GET /signout` — ends the session.
- Screenshot: `POST /api/v1/videos/{id}/screenshot {video_time}` → 200 `{links, data:[{type:'videos',...},{type:'images', url, filename}]}`; the image is rendered by a Celery chain, so poll the URL (HEAD) until 200 (web grabs a DOM canvas instead). Event edits: `PUT /api/v1/events/{id}` body `{tags:[{tag,value}], videos:[{id,title,description}]}` (EventSchema requires tags + every video's title/description; unknown keys excluded). `POST /videos/{id}/suggest_delete {reason}`, `POST /videos/{id}/tail {tail}`, `GET /videos/tails`, `POST /events/{id}/make_public {expires_at, can_download, shared_with}` → `{share_token}` (web URL `https://{urls.www}/v/{token}`; NO revoke endpoint exists).
- `GET /api/v1/bootstrap` → `{current_user{id,email,username,first_name,last_name,profile_img_url}, is_admin, is_superadmin, cross_org_admin, csrf_token, urls{api,static,www,logout,login,...}, settings{website_name,tz,date_format_js,...}}` (verified at runtime); authSlice stores it loosely. Unauthenticated JSON requests → 401 `{meta:{code:401}, response:{errors:[..]}}` (302 to `/signin` without `Accept: application/json`).
- `GET /api/v1/videos/list?page&per_page&sort` → `{items[], page, per_page, total, pages, has_next, has_prev, sort}`; item `{id, title, status, duration, uploaded_filesize, date_posted(ISO), start(ISO), thumbnail_url, deleted_at, user{}, tail?}`. Sorts: recently-uploaded|recently-recorded|title-asc|title-desc|shortest|longest|category-asc|category-desc (unknown sort silently = recently-uploaded). ISO dates lack 'Z' — normalize via `normalizeIsoDate`. Items carry **NO `event_id`** (verified in videos_list_api.py); `tail` is omitted when falsy; live videos are excluded.
- `GET /api/v1/live/list?page` → **different envelope** `{items, total, page, per_page (fixed 24), pages}` — no has_next/has_prev/sort. Item = list item + `live_stream_id`, `live_stream_status` (raw LiveStream.status, not live_stream_state), `tail` always present; **NO `event_id`**.
- `GET /api/v1/videos/{id}/event_id` (video_shell_config_api, exists today) → `{event_id, video_id, permissions{}}` — the one-call-on-tap alternative to adding event_id to the list serializers.
- `GET /api/v1/events/{event_id}.json` → `{events:[{id, tags, custom_field_values, videos:[videoDict]}]}`. videoDict: `{id, event_id, title, description, duration, start, end (epoch floats), date_posted(epoch string), is_primary, program_type, status, live_stream_state (null|'live'|'processing'|'recording_ready'), live_stream_id?, live_start?, hls_stream_url, mp4_url, stream_url, thumbnails_vtt_url, subtitles_vtt_url, thumbnail_url, time_mapping (snake_case), waveform, transcript, clipmarks[], tail, has_audio, has_video, download_url}`.
- `GET /api/v1/videos/{id}/flight_data.json[?after=<epoch>]` (accepts `?token=` share token) → `{flight_data:{loc, target, footprint, acft_hdg, graphs, first_flight_point_utc, last_flight_point_utc}}` — compressed `[utc, value]` series. Load pattern (useFlightData): initial fetch, then loop `?after=last_flight_point_utc` concatenating until no new tail; while `live_stream_state==='live'`, keep polling (~7s; 403 → one non-destructive `refreshEvent` then 7s·2ⁿ backoff ≤60s). Per-run state is closure-local and keyed to the video id; `setActiveVideo` drops mapData + graph.data. **Backend quirk (LIVE-003):** whatever id is requested, the endpoint serves the PRIMARY's points — a phone program's own GPS track is unreachable until the additive `?own=1` fix lands (review/backend-live.md); FlightMap captions the track as the primary's meanwhile.
- `POST /api/v1/videos/{id}/viewing` body `{paused}` → `{liveStreamState, loggedIn}`. Fire every 5s on the player (useViewingHeartbeat); on liveStreamState change, reload the event so the source swaps live↔VOD.
- Clipmarks: `GET/POST /api/v1/videos/{id}/clipmarks` (POST `{event_id, time_start, time_end, type, text}` epoch floats; type 'clip' triggers server-side eager render of ts+mp4 to EFS); `POST .../clipmarks/{cid}` update; `DELETE`; `POST .../clipmarks/{cid}/clip` `{title, description}` → new Video via Celery; `GET .../formats` → `{formats:[]}`; `GET .../download?format=` — poll header `X-Status: 'File ready for download'`.
- Search (stretch): `POST /api/v1/clip_embedding/search/enhanced` `{query, top_k, rerank}`; tags `GET /api/v1/tags`; filters `GET /api/v1/videos/filter_choices`.
- Multi-program events: always use the video where `is_primary === true`; ignore secondaries.
- Permission quirk: `flight_data.json` checks LIVESTREAMS READ while live and VIDEOS READ otherwise — a 403 mid-transition means reload the event, not a client bug.

## Live publishing from the phone (features/broadcast + modules/earthscape-live) — 2026-08-26
- **Protocol = SRT caller** (the ONLY ingest the backend has; no RTMP/WHIP, mediasoup is consume-only). Phone → `srt://host:port?mode=caller&passphrase=…&pbkeylen=16&latency=…` → per-stream `srt_listener_proxy` → `graph_server_app` → HLS + master.ts + KLV, i.e. the unchanged ION/OBS pipeline. Stream identity = IP:port, auth = passphrase (no streamid).
- **Backend (earthscape-mobile branch, additive)**: `app/api/live_mobile_api.py` at `/api/v1/live`: `POST /streams {stream_name?, event_id?, program_type?, latency_ms?}` → `{id, status, video_id, event_id, is_primary, program_type, playlist_ready, playlist_url, ingest{url,host,port,passphrase,latency_ms}, telemetry_url}` (201; `event_id` joins a LIVE event as a non-primary program, 409 if the primary isn't live); `GET /streams/{id}` status poll; `POST /streams/{id}/end`; `POST /streams/{id}/telemetry {fixes:[{lat,lon,alt,heading,timestamp_ms,pts?}]}` → converted to MISB rows → `import_ts_klv_live` (or raw KLV rows). `create_livestream(..., event=, is_primary=, program_type=, title=)` optional kwargs; `viewable_live_videos` filters `is_primary`; `flight_point_cache` serializes `Decimal`. Verified with curl in dev (create/join/telemetry→flight_data/end/409/401).
- **Native module** `modules/earthscape-live` (Expo local module, iOS only, pods `HaishinKit 2.0.8` + `SRTHaishinKit 2.0.8` — the last SRT release on CocoaPods; HaishinKit 2.1+ is SwiftPM-only, do not bump blindly). `LivePublisher.swift` = MediaMixer (VideoToolbox H.264 Main, no B-frames, keyframe 2s, AAC 96k) → `SRTStream`; 1 Hz `performanceData` stats; `AdaptiveBitrateController` (fast 25% cuts on loss/buffer/RTT, slow 15% ramps after 8 clean seconds, thermal ceiling); reconnect with 1s·1.5ⁿ jittered backoff (camera keeps running, server keeps the stream); `NWPathMonitor` → immediate retry when the path is restored; background parks the link, foreground resumes. JS: `EarthscapeLive.*` + `addLiveListener`, `EarthscapeLivePreviewView`. Android → `isSupported=false` stub.
- **App**: `broadcast` slice + `useBroadcast` (create → publish → GPS telemetry via expo-location @1 Hz, batched every 2s with drop-on-full queue → status poll 4s → end). `app/golive.tsx` (`?eventId=&title=` = join); entry points: Live tab "Go live" card, player action row **"Add my camera"** on live events. Viewer side: `ProgramStrip` shows every other program of the event as a tile (`planProgramTiles`: live first, only `MAX_TILE_PLAYERS = 2` decode — the rest are thumbnails; `processing` = placeholder; live tiles retry a 404 playlist every 10s); VOD tiles drift-correct via their TimeMapper unless the ACTIVE program is live (its clock = stream-creation time, skewed); tap swaps primary (`setActiveVideo`). The 20s event re-read (while ANY program is live), heartbeat flips and 403s use `refreshEvent` (merge by id, player/map/timeline untouched). "Add my camera" gates on the PRIMARY being live (backend 409s otherwise) and passes existing labels so the joining phone defaults to "Mobile · <first name>" (numbered on collision) as stream_name + program_type. Leaving the Go Live screen with an open stream ends it (`endStreamWithRetry`); `/end` failures retry with backoff (`END_MAX_ATTEMPTS`). Gated by `features.live_enabled` and `EarthscapeLive.isSupported`.
- **Audio route is shared (LIVE-020)**: expo-video's VideoManager re-asserts `.playback` on the ONE shared `AVAudioSession` on every playingChange, and the publisher takes `.playAndRecord`/`.videoRecording` — so "Add my camera" pauses the player before `router.push('/golive')` (no echo into the published track, no session tug-of-war) and resumes it via `useFocusEffect` only if it had paused a *playing* player; `configureAudioSession` is deliberately NOT `.mixWithOthers` and `stopPreview` deactivates the session. Live tiles are always muted. ## Conventions
- Screens in `app/` (expo-router — the file tree IS the router; route files stay thin); domain code in `src/features/{auth,library,player}` (mirrors the web repo's feature-folder convention); shared code in `src/common`; `src/common/config.ts` is the only place URLs are built; every request goes through `src/common/api/client.ts` — no raw fetch in components.
- ATS: `app.json` `NSExceptionDomains` allow plain http ONLY for `localhost`, `earthscape.localdocker`, `nip.io` (+subdomains); `earthscape.com` stays https-only. `NSAllowsLocalNetworking` alone does NOT cover composed hosts like `demo.localhost` (verified with URLSession). `app.config.js` (dynamic layer over app.json, tested in `appConfig.test.ts`) DROPS the whole `NSAppTransportSecurity` block unless the build talks http (`EXPO_PUBLIC_API_INSECURE=1`, or base domain unset / localhost / localdocker / nip.io) — `nip.io` is public wildcard DNS, so shipping it would whitelist cleartext to any IPv4. Info.plist is generated ONLY by prebuild, and `expo run:ios` prebuilds only when `ios/` is missing (@expo/cli `run/ensureNativeProject.js`) — with this repo's prebuilt `ios/`, env vars at `run:ios` time never reach the plist (SEC-019). Re-sync it explicitly: `NODE_ENV=production npx expo prebuild -p ios` before ANY Release/stage/TestFlight build (a bare prebuild sets NODE_ENV=development unless already exported; no `--clean` — it deletes `ios/` and bails on a dirty git tree). **Prebuild sync only MERGES infoPlist keys into an existing `ios/` — it never REMOVES a key the config dropped (verified 2026-09-01: production prebuild left the ATS block in place), so after the prebuild also run `plutil -remove NSAppTransportSecurity ios/Earthscape/Info.plist`**, then verify `plutil -extract NSAppTransportSecurity json -o - ios/Earthscape/Info.plist` FAILS (key absent). Plain `npx expo prebuild -p ios` puts the dev exceptions back before the next Debug/dev device build (merge re-adds keys; the same plutil then prints the block).
- Deployment target: Expo default — do not override. `EXPO_PUBLIC_API_BASE_DOMAIN` (host only, no scheme) + optional `EXPO_PUBLIC_API_LOOKUP_HOST` (lookup origin; default `api.{base}`) + optional `EXPO_PUBLIC_API_INSECURE=1` per eas.json profile; dev defaults to `earthscape.localdocker` (port 80) over http. These are babel-inlined, so a change needs a Metro restart / fresh build, not just a reload.
- **AWS stage**: not a separate base domain — stage orgs are `stage`, `stage-acl`, `stage-acl-2`, `stage-acl-3`, `stage-public` under `earthscape.com` (backend docs/aws_cloud_naming_conventions.md), separate RDS → separate users. eas `staging` profile = `BASE_DOMAIN=earthscape.com` + `LOOKUP_HOST=stage.earthscape.com`; local device build: `export EXPO_PUBLIC_API_BASE_DOMAIN=earthscape.com EXPO_PUBLIC_API_LOOKUP_HOST=stage.earthscape.com; NODE_ENV=production npx expo prebuild -p ios && npx expo run:ios --device --configuration Release` (the prebuild step is what drops the dev ATS exceptions from Info.plist — SEC-019; `run:ios` alone reuses the existing `ios/` untouched). https only. Backend side: stage deploys `branch: test` (ansible/inventory/stage/group_vars), so the mobile endpoints exist there only after `ansible-playbook -e "env=stage" -i inventory/stage/aws_ec2.yml deploy.yml -e branch=earthscape-mobile --skip-tags=npm-skippable,alembic-skippable --ask-vault-pass` (no migrations needed). Live servers are EC2-tag-discovered (`live_addr: ''`, `Environment=stage`), SRT ingest = live EC2 public IP over UDP (SG in aws_cloudformation/LiveServerAutoScaling.yml) — same path OBS uses.
- `reference/` is gitignored web-repo context (eventSlice.js, Map.jsx, Dashboard.jsx, sample payloads) — read it via explicit paths (search tools skip gitignored files), never import from it.
- Backend repo access when needed: `/add-dir ~/dev/earthscape` in-session; backend edits stay deliberate, additive, on feature branches — never in auto mode.
